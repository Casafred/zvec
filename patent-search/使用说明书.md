## 1. 系统简介

专利语义检索系统是一个面向团队的专利信息检索工具，基于 Zvec 嵌入式向量数据库构建，支持：

- **Excel 批量导入**：上传 .xlsx/.xls 文件，自动解析专利字段
- **自动向量生成**：导入时自动调用嵌入 API 生成向量，无需手动操作
- **混合检索**：4 路检索通道（语义 + 关键词），加权融合排序
- **权重可调节**：自由选择检索通道和调整权重
- **中文界面**：暗色主题，全中文操作

## 3. 安装部署

### 3.1 获取代码

将 `patent-search/` 目录复制到目标机器。

### 3.2 安装后端依赖

```bash
cd patent-search/backend
pip install -r requirements.txt
```

> 如果使用 Python 3.10–3.13 且需要 BM25 关键词检索功能，额外安装：
> ```bash
> pip install dashtext
> ```
> Python 3.14 暂不支持 dashtext，BM25 通道将自动禁用，不影响其他功能。

### 3.3 安装前端依赖

```bash
cd patent-search/frontend
npm install
```

## 4. 启动服务

### 单机使用

打开两个终端窗口：

**终端 1 — 后端**（端口 7860）：

```bash
cd patent-search/backend
python -m uvicorn app.main:app --host 127.0.0.1 --port 7860
```

**终端 2 — 前端**（端口 5173）：

```bash
cd patent-search/frontend
npm run dev
```

浏览器打开 http://localhost:5173 即可使用。

### 团队共享

让局域网内同事通过浏览器访问：

**后端**绑定所有网卡：

```bash
python -m uvicorn app.main:app --host 0.0.0.0 --port 7860
```

**前端**暴露网络：

```bash
npm run dev -- --host 0.0.0.0
```

同事浏览器打开 `http://你的IP:5173` 即可使用。

### 生产部署（可选）

前端打包为静态文件，由后端直接提供：

```bash
cd patent-search/frontend
npm run build
# 将 dist/ 目录的内容复制到 backend/app/static/ 下
mkdir -p ../backend/app/static
cp -r dist/* ../backend/app/static/
```

然后只需启动后端，访问 http://IP:7860 即可，无需单独运行前端。

## 5. 功能详解

### 5.1 设置 — 配置 API Key

进入 **设置** 页面，配置嵌入服务的连接信息。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| API 密钥 | （空） | 硅基流动 API Key |
| 模型名称 | `Qwen/Qwen3-Embedding-0.6B` | 嵌入模型 |
| API 地址 | `https://api.siliconflow.cn/v1` | API 服务地址 |

**操作步骤**：

1. 在 [硅基流动控制台](https://cloud.siliconflow.cn) 创建 API Key
2. 将 API Key 粘贴到"API 密钥"输入框
3. 点击 **保存**
4. 点击 **验证**，系统会调用 API 发送测试文本"测试"
   - 验证成功：显示"验证成功！向量维度：512"
   - 验证失败：显示错误原因（如 Key 无效、余额不足等）

> **注意**：API Key 仅保存在服务器本地（`data/config.json`），不会上传到任何第三方服务。

### 5.2 导入 — 上传专利数据

进入 **导入** 页面，将 Excel 中的专利数据导入系统。

#### 步骤 1：上传 Excel

- 点击上传区域或拖拽 `.xlsx` / `.xls` 文件到上传区域
- 系统自动解析文件，显示：
  - 总行数和列数
  - 前 5 条数据预览表格

#### 步骤 2：确认列名映射

系统会自动识别 Excel 列名与专利字段的对应关系：

| 专利字段 | 自动匹配的 Excel 列名 |
|----------|---------------------|
| 专利号 | 专利号、申请号、专利申请号 |
| 申请人 | 专利申请人、申请人、申请者 |
| 标题 | 标题、专利名称、发明名称、专利标题 |
| 摘要 | 摘要、专利摘要、发明摘要 |
| 说明书 | 说明书、专利说明书、发明说明书、详细说明 |
| 权利要求 | 权利要求、权利要求书 |

如果自动匹配不正确，可以手动点击下拉框选择对应的 Excel 列名。

> **重要**：专利号和标题为必填字段，其余字段可选。至少需要标题或摘要有值才能生成语义向量。

#### 步骤 3：开始导入

1. 确认映射关系后，点击 **确认映射**
2. 点击 **开始导入**
3. 系统自动执行：
   - 读取已配置的 API Key
   - 对每条专利的标题+摘要、说明书、权利要求分别调用嵌入 API 生成向量
   - 同时本地计算 BM25 稀疏向量（关键词索引）
   - 批量写入 Zvec 向量数据库
4. 导入过程中显示加载状态
5. 完成后显示："导入完成！共导入 N 条专利数据"

#### 注意事项

- 导入过程中请勿关闭页面
- 如果中途中断，已导入的数据不会丢失，可再次导入剩余数据
- 重复的专利号会报错跳过，不影响其他数据导入
- 导入速度取决于 API 响应速度和数据量，1000 条约需 5-15 分钟

### 5.3 搜索 — 语义检索专利

进入 **搜索** 页面，输入自然语言搜索专利。

#### 基本搜索

在搜索框输入关键词或描述，点击 **搜索**：

- 输入 `"新能源汽车电池管理"` → 搜索电池管理相关专利
- 辏入 `"图像识别神经网络"` → 搜索 AI 视觉相关专利
- 输入 `"CN202310123456"` → 精确搜索特定专利号

#### 按申请人过滤

在"按申请人过滤"输入框填入申请人名称，搜索结果将限定为该申请人的专利。

#### TopK 设置

选择返回结果数量：5、10、20、50 条。

#### 检索字段与权重配置

点击搜索框下方的 **▸ 检索字段与权重配置** 展开高级设置面板。

系统提供 4 个检索通道，每个通道可以独立开关和调节权重：

| 通道 | 默认权重 | 说明 |
|------|---------|------|
| 标题+摘要 | 40% | 语义匹配技术主题和概要 |
| 权利要求 | 30% | 语义匹配法律保护范围 |
| 关键词(BM25) | 20% | 精确关键词匹配（本地计算，不消耗 API） |
| 说明书 | 10% | 语义匹配技术实现细节 |

**调节方式**：

- 勾选/取消复选框启用或禁用该通道
- 拖动滑块调整权重（0~1）
- 权重自动归一化（总和始终为 100%）
- 底部实时显示当前加权公式

**典型场景**：

| 场景 | 建议配置 |
|------|---------|
| 通用语义检索 | 全部开启，默认权重 |
| 精确关键词搜索 | 关闭所有语义通道，只开 BM25，权重 100% |
| 法律范围比对 | 权利要求 70% + 标题+摘要 30%，关闭其余 |
| 技术细节深挖 | 说明书 50% + 标题+摘要 30% + 权利要求 20% |

#### 搜索结果

每条结果以卡片形式展示：

- **标题**（大字）
- **专利号 · 申请人**（灰色小字）
- **摘要**（截断显示，约 100 字）
- **相似度**（百分比，如 92.3%）

点击卡片展开完整内容：

- 完整摘要
- 完整说明书（带滚动条，最大高度 300px）
- 完整权利要求（带滚动条，最大高度 300px）

再次点击卡片可折叠。

## 6. 检索原理

### 6.1 四路混合检索架构

```
用户输入 "新能源汽车电池管理"
         │
    ┌────┴────┐──────────┐──────────┐
    ▼         ▼          ▼          ▼
 title_abs   desc     claims      BM25
 稠密512d   稠密512d  稠密512d   稀疏向量
 语义匹配   技术细节   法律范围   关键词匹配
    │         │          │          │
    └────┬────┘──────────┘──────────┘
         ▼
   WeightedReRanker 加权融合
         ▼
     排序返回 TopK
```

### 6.2 向量生成策略

为节省 Token 同时保证检索精度，每篇专利生成 4 组向量：

| 向量 | 输入文本 | Token 估算 | 策略 |
|------|---------|-----------|------|
| title_abs_vec | 标题 + 摘要 | ~500 | 全文输入，无截断 |
| claims_vec | 首条独立权利要求 | ~1500 | 智能提取第 1 条权利要求 |
| desc_vec | 说明书关键章节 | ~3000 | 提取"发明内容"+"具体实施方式"前 8000 字 |
| bm25_vec | 标题 + 摘要 + 首条权利要求 | — | 本地 BM25 分词，无需 API |

### 6.3 指令增强（Instruction Aware）

搜索时对查询文本加指令前缀，让嵌入模型聚焦检索意图：

| 向量字段 | 查询指令 |
|---------|---------|
| title_abs_vec | `Instruct: Retrieve the most relevant patents` |
| desc_vec | `Instruct: Find patents with similar technical details and implementation` |
| claims_vec | `Instruct: Find patents with similar claim scope` |

文档侧（导入时）不加指令，直接编码原文。

### 6.4 说明书智能提取

说明书原文可能长达数万字，系统按优先级提取关键章节：

1. **"发明内容"章节** — 包含技术方案核心
2. **"具体实施方式"前 8000 字** — 包含技术实现细节
3. **无章节标记** — 取前 16000 字符

总输入控制在约 8000 token 以内，远在 32K 限制之下。

## 7. Excel 数据格式要求

### 7.1 支持的格式

- `.xlsx`（Excel 2007+）
- `.xls`（Excel 97-2003）

### 7.2 列名要求

Excel 的第一行为列名，系统自动识别以下列名：

| 专利字段 | 可识别的列名 |
|----------|------------|
| 专利号 | 专利号、申请号、专利申请号 |
| 申请人 | 专利申请人、申请人、申请者 |
| 标题 | 标题、专利名称、发明名称、专利标题 |
| 摘要 | 摘要、专利摘要、发明摘要 |
| 说明书 | 说明书、专利说明书、发明说明书、详细说明 |
| 权利要求 | 权利要求、权利要求书 |

如果 Excel 列名不在上述范围内，可在导入页面手动选择映射。

### 7.3 数据要求

- 专利号为唯一标识，不可重复
- 标题和摘要建议必填，至少需填一项
- 说明书和权利要求可选，但建议填写以提高检索精度
- 每行一条专利，不要有合并单元格

### 7.4 示例 Excel 结构

| 专利号 | 专利申请人 | 标题 | 摘要 | 说明书 | 权利要求 |
|--------|-----------|------|------|--------|---------|

## 8. 常见问题

### Q: 验证 API Key 失败怎么办？

- 检查 API Key 是否正确复制（前后无空格）
- 检查硅基流动账户余额是否充足
- 检查网络是否能访问 `api.siliconflow.cn`

### Q: 导入速度慢？

- 正常速度：1000 条约 5-15 分钟
- 速度取决于 API 响应速度和并发限制
- 系统按 50 条一批调用 API，100 条一批写入数据库
- 说明书和权利要求的文本越长，生成向量越慢

### Q: 导入中断了怎么办？

- 已导入的数据保存在磁盘上，不会丢失
- 记录已成功导入的条数
- 重新导入时，重复的专利号会自动跳过

### Q: BM25 通道不可用？

- BM25 依赖 `dashtext` 库，该库暂不支持 Python 3.14
- 使用 Python 3.10–3.13 并安装 `pip install dashtext` 即可启用
- BM25 不可用时，其余 3 个语义检索通道正常工作

### Q: 如何删除已导入的数据？

- 停止后端服务
- 删除 `patent-search/backend/data/patent_db/` 目录
- 重启后端即可重新导入

### Q: 如何增量导入新数据？

- 直接上传新的 Excel 文件并导入
- 系统会追加到已有集合中
- 如果新数据中有与已有数据相同专利号的记录，会报错跳过

### Q: 搜索结果相似度分数很低？

- 检查 API Key 对应的模型是否正确（应为 Qwen3-Embedding-0.6B）
- 尝试调整检索通道权重
- 确认导入时数据映射是否正确（尤其是标题和摘要是否映射到了正确的列）

### Q: 如何让同事通过浏览器访问？

- 后端启动时使用 `--host 0.0.0.0`
- 前端启动时使用 `npm run dev -- --host 0.0.0.0`
- 同事通过 `http://你的IP:5173` 访问
- 确保防火墙允许 5173 和 7860 端口
